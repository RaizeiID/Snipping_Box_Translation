A. IDENTITAS PROYEK DAN KEBUTUHAN PENGGUNA
------------------------------------------
Nama proyek    : ORT Translation / ORTCore / TitanCORE translator
Jenis aplikasi : Aplikasi penerjemah dialog game berbasis OCR real-time dengan overlay terjemahan, WebUI, cache, model/engine selection, diagnostic tools, dan learning/glossary.
Platform utama : Windows pada laptop pengguna.
Hardware yang pernah ditetapkan pengguna:
- Acer Predator Helios Neo PHN16-71.
- RAM 64 GB.
- NVIDIA RTX 4050 Laptop GPU 6 GB VRAM.
- Game berat seperti Wuthering Waves perlu preset aman karena VRAM juga digunakan game.

Kebiasaan dan preferensi kerja pengguna:
- Pengguna menguji langsung dengan game dan mengirim screenshot/log panjang.
- Pengguna menginginkan analisis profesional, lalu file ZIP siap pakai.
- Untuk update besar seperti v8.0, v8.4, dan v8.7, pengguna meminta full folder/project ZIP untuk membuat folder baru.
- Setelah update besar selesai, update lanjutan minor biasanya harus berupa ZIP yang hanya berisi file berubah/ditambah, kecuali diminta berbeda.
- Semua update harus terdokumentasi dengan versi, perubahan, file terubah, hasil tes/compile, known issues, dan rekomendasi berikutnya.
- Fitur/UI penting jangan dirombak sembarangan: kotak terjemahan utama, indikator ping/ms/game/engine, kontrol engine/mode/shortcut, daftar keluarga model Normal/Lite/IDN/Lite IDN/Fast, Dashboard AI Recap, dan fokus Runtime & Tools.

B. ARSITEKTUR UMUM APLIKASI YANG PERLU DIPAHAMI
-----------------------------------------------
Komponen yang sering menjadi pusat perubahan:
- `TITANMAIN.py`               : runtime OCR/overlay/translation utama, masih cukup besar.
- `webui.py`                   : Dashboard dan Runtime & Tools.
- `launcher_backend.py`        : menerjemahkan pilihan UI menjadi environment/runtime start dan log status.
- `model_registry.py` / `model_strategy.py` : model family, preset OCR/interval/engine dan strategi.
- `translation_engine.py`      : backend terjemahan, cache/naturalization/engine path.
- `runtime_bridge.py`          : preprocessing/postprocessing antar runtime dan engine.
- `v7_system_profile.py`       : game/hardware profile dan environment yang diterapkan.
- `cache_store.py`             : scoped cache/fuzzy cache/guard cache.
- `benchmark_session_report.py`: Analyze Last Session.
- `data_processing_backend.py` : WebUI glossary/name/special/blacklist/candidate handling.
- `app/`                       : modul yang semakin dipisah mulai v8.0: OCR, runtime, translation, telemetry, learning, diagnostics.

Keluarga model penting:
- Normal V1–V5.
- Lite V1–V5.
- IDN V1–V5.
- Lite IDN V1–V5.
- Fast V1, Fast V2, Fast IDN.

Semantik mode yang sudah diputuskan dan tidak boleh diubah tanpa permintaan pengguna:
- Freeze   : pengguna memicu/dialog manual; snapshot cepat dan stabil untuk klik cerita manual.
- Interval : Freeze otomatis secara berkala/stabil; cocok untuk cerita yang dibaca manual atau semi-otomatis.
- Auto     : cerita berjalan otomatis; harus mendukung teks yang muncul bertahap tanpa menahan hasil terlalu lama.
Fast/Lite/IDN hanya menjadi modifier profil/tuning di atas semantik mode tersebut, bukan mengganti arti mode.

G. KEPUTUSAN YANG SUDAH DIKUNCI / JANGAN DILUPAKAN
----------------------------------------------------
1. GFL dan GFL2 adalah profile berbeda.
   - Jangan kembali memproses Girls' Frontline seri pertama memakai `GFL2_EXILIUM` bila pengguna memilih GFL.
   - GFL memerlukan footer mask dan Name/Body ROI; GFL2 memiliki isu wide-dialog/numeric lain.

2. OCR angka kecil bukan lagi prioritas utama.
   - Setelah perbaikan numeric ROI pada v8.5.1, angka yang tetap tidak terbaca dianggap known minor limitation, kecuali ada regresi besar atau pengguna secara eksplisit kembali memprioritaskannya.

3. Jangan menyimpulkan performa Fast ketika engine masih Argos fallback.
   - Jika log menunjukkan `engine=argos_offline` atau Fast CT2 unavailable karena model/SPM tidak ada, benchmark Fast vs Lite tidak valid.

4. V4 tetap hybrid/online+offline secara desain.
   - Model V4 tidak boleh dipaksa offline-only secara permanen.
   - Namun, bantuan online hanya dianggap benar-benar berjalan bila log/status membuktikan applied online assist; policy hybrid saja bukan bukti.

5. Cache harus dinilai setelah OCR bersih.
   - Masalah all-MISS pada GFL dipengaruhi footer artifact dan progressive typing. Uji ulang cache hanya setelah profile GFL v8.7 aktif.

6. Speaker/NPC learning harus konservatif.
   - Nama valid dapat di-seed atau dikonfirmasi.
   - Narasi dan credit tidak boleh otomatis masuk database speaker.

7. Fitur UI yang tidak boleh dirusak tanpa instruksi eksplisit pengguna:
   - Translation overlay utama dan gaya inti.
   - Indikator ping/ms/game/engine.
   - Kontrol engine/mode/shortcut.
   - Seluruh kelompok model V1–V5, Lite, IDN, Lite IDN, Fast.
   - Dashboard AI Recap tetap di Dashboard; Runtime & Tools fokus runtime/diagnostic.
   - Reset Live Log di sebelah Copy Live Log.
